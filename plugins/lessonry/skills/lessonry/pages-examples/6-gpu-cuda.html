0一分钟速览

一句话：大模型的本质是海量矩阵乘法——千百万个"乘一下加一下"的简单运算，且彼此独立、可以同时做。这正是 GPU 的主场：几千个小核心一起上。CUDA 就是 NVIDIA 给这套硬件配的编程平台（类 C++ 语言 + 库 + 驱动），PyTorch 的一行代码最终都由 CUDA kernel 在 GPU 上执行。
GPU 是什么

几千个小核心的并行机器

CPU 核心少而强（4~64 个"教授"），GPU 核心多而简单（上万"小学生"）。矩阵乘法这种海量重复任务，GPU 快百倍。

CUDA 是什么

GPU 的编程平台

用"类 C++ + 特殊标记"写函数（kernel），声明"开多少线程"，GPU 负责把线程铺到几万个核心上。2006 年发布，AI 时代的事实标准。

AI Infra 的"物理定律"

模型为什么吃显存、芯片宣传的 TFLOPS（算力）和 TB/s（搬运速度）哪个更关键、以及为什么很多优化本质是"少搬数据"。

2★第一个 CUDA kernel：让 1024 个线程做加法

讲解要点：CUDA 程序的分工：CPU（host）上的"主人"代码 + GPU（device）上的"工人"函数 = kernel（用 __global__ 标记）。每个线程只负责一个下标的计算；它靠内置变量算出自己管哪个下标。线程层次：thread（线程）→ block（线程块）→ grid（全部）。
⇆ 横向滑动查看完整图
__global__ void vec_add(float* A, float* B, float* C, int n) {    int i = blockIdx.x * blockDim.x + threadIdx.x;    if (i < n) {        C[i] = A[i] + B[i];   // 每个线程只加一个    }}// 启动：4 个 block × 每块 256 线程 = 1024 个线程vec_add<<<4, 256>>>(d_A, d_B, d_C, 1000);
grid（全部线程） block（线程块，一队） 当前线程（threadIdx）
念一遍这个下标公式：全局编号 i = blockIdx（我是第几队）× blockDim（每队多少人）+ threadIdx（队里第几位）——就像"3 班 × 每班 40 人 + 12 号"= 全校绝对位置。整个 CUDA 编程的核心就是它。
📌 一句话总结：kernel = 写给"每个线程"的规则；启动配置 <<>> 决定雇多少人；下标公式让每个线程找到自己的那份数据。 ✅ 自查：启动 <<<8,128>>> 时，block 3 的 thread 17 负责哪个下标？（答：3×128+17=401）

3SM 与调度：warp、延迟隐藏与分支发散

讲解要点：GPU 芯片的实际干活单元叫 SM（流式多处理器），一块 H100 有 132 个。线程以 32 个为一组（warp，"线程束"）"锁步"执行：一条指令、32 份数据同时算；SM 里常有多个 warp，一个在等显存时就切另一个——用"人多"把等待时间藏起来（延迟隐藏）。
⇆ 横向滑动查看完整图
SM（流式多处理器） warp = 32 线程（锁步） 等显存的 warp 正在计算的 warp
⚠ 分支发散（branch divergence）：同一个 warp 里的线程走 if / else 两个岔路时，GPU 只能让两条路先后串行各跑一遍——32 线程的并行优势瞬间打折。写 kernel 的第一戒律：让相邻线程走相同的路。
📌 一句话总结：线程按 32 个打包成 warp 锁步执行；SM 靠"多个 warp 轮流上岗"把显存等待藏起来；分支发散是并行杀手。 ✅ 自查：为什么 warp 是 32 个而不是 1 个？（答：一批指令发一次，32 个一起执行才摊薄成本）

4内存金字塔：计算不贵，搬运才贵

学完这章你能：理解 AI 芯片宣传里"TFLOPS"之外的另一半真相——带宽。🖐 点击金字塔的每一层，看容量、速度和类比。核心结论：越靠近计算单元的存储越小但越快（快十倍以上）；性能优化的本质是"把数据搬到离计算更近的地方，少跑图书馆"。
⇆ 横向滑动查看完整图 · 点击金字塔层
记一个数量级：寄存器/共享内存比 HBM 显存快十倍到上百倍，但小上千倍。深度学习的很多"神技"（下一章 Tensor Core、后面的 FlashAttention）本质都是同一句话：别反复跑图书馆。
📌 一句话总结：内存金字塔：越快越小、越慢越大；性能 = 少搬数据 + 搬得离计算近。 ✅ 自查：HBM 容量大但慢，那"快"的代价是什么？（答：容量小，装不下整个模型）

5Tensor Core：专吃矩阵块的"粗加工车间"

讲解要点：普通 CUDA core 一次算 1 个乘加；Tensor Core 是专门为矩阵造的单元——一次指令吃完一整个 4×4 矩阵块的乘加。同时钟下 FP16 吞吐约为普通核心的十几倍。大模型里的矩阵乘法几乎全由它完成。
⇆ 横向滑动查看完整图
CUDA core：一次 1 个乘加 Tensor Core：一次一个 4×4×4 块 FP16 计算 / FP32 累加（混合精度）
混合精度一句话：用 FP16/BF16（16 位浮点数，"半精度"）做乘加（快、省显存），关键累加用 FP32（32 位，精度更高）防止精度损失——训练大模型的标准姿势，也是量化（下一页）的先声。
📌 一句话总结：Tensor Core = 矩阵专用粗加工车间：一口吃 4×4×4 的块，把大模型最爱的 GEMM 喂得飞快。 ✅ 自查：为什么矩阵乘法特别适合 Tensor Core？（答：可整块并行、乘加模式固定）

6★roofline：你的程序是"算不动"还是"搬不动"？

学完这章你能：看懂 AI 性能分析最常用的图。算术强度 = 每搬运 1 字节数据能做多少次浮点运算；可达性能 = min（峰值算力，带宽 × 算术强度），即两者取小。拖动滑块改变它：左侧=搬运瓶颈（memory-bound，提速要加带宽），右侧=计算瓶颈（compute-bound，提速要加算力）。这一页是理解 FlashAttention（后续课程）和推理瓶颈（下一页）的钥匙。
⇆ 横向滑动查看完整图
算术强度（FLOP/Byte）
0.20

图中为示意参数（教学简化）：峰值算力 100、带宽 10 → 脊点 = 100÷10 = 10。真实 H100：峰值 ≈ 1000 TFLOPS（FP16 Tensor Core）、带宽 ≈ 3.35 TB/s → 真实脊点 ≈ 300 FLOP/Byte——真实硬件的脊点比图中更靠右，绝大多数负载落在左侧搬运瓶颈区。

先记住一个反直觉结论：大模型逐字生成（decode）阶段几乎总是搬运瓶颈——每生成一个字都要把全部权重从 HBM 搬一遍，计算反而闲着。这就是"推理优化≈省搬运"的根源；下一页的 KV Cache（少重算）与量化（少搬运）都由此而来。
📌 一句话总结：roofline：算术强度低 → 搬运瓶颈（加带宽才有用）；高 → 计算瓶颈（加算力才有用）。先看位置，再谈优化。 ✅ 自查：decode 阶段在 roofline 哪一侧？想提速该加算力还是加带宽？
