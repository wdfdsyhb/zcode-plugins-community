# 仪表盘 (instrument)

从本机 ZCode 用量数据库读出真实记录，换算成用户能直接读的指标。
数据由 ZCode 在**每次请求结束时**写入，因此不需要抓包、不依赖 provider 返回的统计。

## 怎么取数

首选 **`metrics` 工具**（MCP server `instrument`，工具名形如 `mcp__instrument__metrics`）。
它返回现成的文本，直接引用即可，不要自己重算。

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `view` | `reply`(默认) / `turns` / `session` / `all` | 最新一条回复 / 最近若干轮表格 / 会话累计 / 全部 |
| `limit` | 1–50，默认 5 | `turns`、`all` 包含的轮数 |
| `session` | 会话 id | 省略时按工作目录匹配最近活跃的会话 |
| `cwd` | 目录 | 用于匹配会话，默认当前工作目录 |
| `detail` | true/false | 追加工具耗时表、模型对比表、逐请求明细、失败与重试 |

`quota` 工具查询 CommandCode 订阅额度（5 小时 / 每周 / 每月已用与上限、重置时间、本期请求与 token 用量），
当用户问"还剩多少额度""5 小时窗口用了多少"时使用；它只读、不消耗额度。

> 插件还提供一个**会话侧栏面板**（面板切换器里的「仪表盘」），五个标签：总览 / 回复 / 模型 / 工具 / 额度，
> 里面有**本轮时间构成**（等待首字 / 生成 / 工具 / 间隙，进行中显示当前阶段）、**上下文占用**
> （输入 / 模型窗口）和**健康度**。它自己每 3 秒刷新，走同一份数据。用户问"工作中在等什么""为什么这么久"
> 时，先看本轮时间的四段：**等待首字占大头就是 provider 慢（预填充/排队），不是工具或本地卡顿**；
> 工具占比高才是工具慢。面板专用的 `panel_snapshot` 工具对模型不可见，不要尝试调用。

工具不可用时退回 Bash 执行插件脚本（先用 Glob 找到它的绝对路径，形如
`**/instrument/scripts/metrics.mjs`）：

```bash
node "<metrics.mjs 绝对路径>" --cwd "$PWD" --format markdown --detail
node "<metrics.mjs 绝对路径>" --cwd "$PWD" --model-scope workspace --format markdown --detail
```

`--format` 支持 `text`（默认，紧凑）/ `markdown`（表格）/ `json`。

## 指标口径（回答时要能解释）

- **首字延迟**：`first_token_at - started_at`。一轮取**第一个成功请求**的值——那才是用户真正等的那段。
- **生成速度**：`输出 tokens ÷ (completed_at - first_token_at)`，与 ZCode 自带 Token 调试面板一致；
  只统计"首个 token 到请求结束"这段纯生成时间，不含首字等待，也基本不含工具执行。
- **输入 / 输出 / 推理 / 合计**：直接取数据库记录。**输入**含被缓存复用的部分，括号里的"缓存命中"
  即 `cache_read`；**推理**是 provider 单独上报的 reasoning tokens，部分 provider 已把它计入输出，
  展示时不要声称二者互不包含。
- **本轮汇总**：该轮 `main_turn` 请求求和，首字取整轮第一个成功请求，实际耗时为首个请求开始到最后一个请求结束。
- **时间构成**：模型 = 各请求耗时之和；工具 = `tool_usage` 耗时之和；其他 = 实际耗时减去前两者，
  包含等用户、等审批、模型停顿等未记录间隔。用户问"时间花在哪"时这是主答案。
- **会话累计**：`model_usage` 全部记录，含子代理、上下文压缩、标题生成——所以会大于各轮之和。
- **工具耗时**：按工具名聚合的调用数、总耗时、最慢一次、报错数。
- **模型对比**：按 model + variant 聚合；默认只算本会话，`--model-scope workspace`（或面板的
  "本工作区"）会加上同目录其他会话，适合回答"哪个模型更快"。
- **回复列表**：每条回复 = 一轮，含用户提问与回复的文本摘要（来自 `part` 表，超长截断）。

## 展示约定

- 默认把 `reply` 的紧凑文本块原样贴出（最新回复 / 本轮汇总 / 会话累计 / 时间构成 / 工具耗时 / 失败重试 / 最近回复摘要）。
- 用户要"看趋势/多轮"→ `turns`；"时间花在哪/哪个工具最慢"→ `detail: true`；
  "哪个模型快"→ `detail: true` + 工作区范围；"这个会话一共花了多少"→ `session`。
- 不要贴 JSON，也不要在回复里重复解释每个字段；用户追问口径时再解释。

## 注意事项

- **正在生成的那条回复还没有记录**：数据在请求结束时落库，此时最新记录是上一个请求。
  如实说明"当前这条还没结束"，不要编造。面板会自动回退显示最近一条已完成请求并标注。
- **约三成的请求没有首字时间记录**（`first_token_at` 为空，常见于整段一次性返回的请求）：
  这时首字与速度显示为 `—`，属于正常缺数据，不要把它解释成"卡住了"或"0 速度"。
- 时间戳单位是毫秒；数据库中 `input_tokens` 对 OpenAI 风格 provider 是含缓存的 prompt tokens。
- **provider 名会自动解析**：库里存的是内部 id（`new-provider-2`、`account:zai-start-plan`），
  插件从 `~/.zcode/v2/provider_config.json`（自建 provider）和安装目录的
  `resources/config/provider/zcode-builtin.json`（内置/账号 provider）取显示名；
  插件配置项 `providerNames` 可覆盖。显示的是 id 本身说明两个文件里都没有它，如实转述即可，
  不要把它当成别的名字。
- 数据库只读访问（`readOnly`），不影响正在运行的 ZCode；只有显式选择工作区范围时才读其他会话。
- 找不到数据库或没有 `main_turn` 记录时，如实报告没有数据，并确认工作目录与会话是否匹配。
