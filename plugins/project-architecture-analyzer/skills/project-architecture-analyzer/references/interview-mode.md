# 模式三：面试审判

触发："面试审判"、"出项目面试题"、"考考我这个项目"。

## 出题前的准备

- 若此前已做过全量分析（存在 `docs/architecture-analysis.html` 或本会话已有扫描结论），直接使用，不重扫。
- 若没有：先做一轮快速扫描（full-analysis.md 阶段 0 的检索 + 抽 2-3 个核心 Controller 精读），确认项目真实用了什么。**不需要生成看板。**

## 出题规则

1. **每道题必须来自真实代码**：题目附"代码依据"（文件 + 方法/配置项），参考答案要点也必须来自代码。
2. **禁止虚构项目行为凑题**：项目没有登录就不出"Token 存哪"题，没有秒杀就不出秒杀题。
3. 默认 10 题；用户可要求加题、减题或换题型。
4. **默认先只给题目，不给答案**；用户回答后（或说"看答案"）再给参考答案要点与代码依据。这是模拟面试，不是直接发题解。

## 题型覆盖

每轮尽量覆盖多种题型，但只出项目真实支持的题型；某题型项目里没有素材就跳过：

| 题型 | 示例问法（结合真实代码替换） |
|---|---|
| 调用链 | "XX 接口从 Controller 到数据库的完整链路是什么？" |
| 技术选型 | "为什么选 A 而不是 B？（结合它在项目里的实际用法）" |
| 职责边界 | "Controller 为什么不能直接调 Mapper/Repository？项目里哪段代码体现了这个分层？" |
| 中间件职责 | "Redis 在这个项目里具体干了什么？为什么用它做？" |
| 故障排查 | "如果 Redis 挂了，XX 功能会怎么样？从代码看哪些环节受影响？" |
| 数据流 | "一次 XX 请求，数据从 DTO 到数据库经历了什么形态变化？" |
| 追问链 | 每题准备 1-2 个追问，用户答对后继续追 |

## 输出

**默认在对话中输出**（先题目后答案，格式如下）；用户要求落盘时，把题目按 `references/dashboard-data.md` 的 interview 结构填进已有看板的 `DATA.interview`（Edit 替换数据区中该字段）并重新写出看板，让题目在看板"⚖️ 面试题"页可点击先答后看。

```
【项目面试官】

Q1：<问题>
（考察点：xxx ｜ 代码依据：UserController.java login()）

Q2：……
```

用户作答后：

```
【点评】
✅ 答对：……（对照代码依据）
⚠️ 遗漏：……（补充要点 + 代码依据）

【参考答案要点】
1. ……（代码依据：xxx）
2. ……

【追问】Q1-1：……
```

## 评分原则

- 用户作答后，对照代码依据指出答对与答漏的部分；全程不虚构项目里不存在的细节。
- 连续答错同一知识点时，切换到学渣模式用大白话把对应概念讲一遍，再回到题目。
- 全部题目结束后给总结：答好的题型、薄弱的题型、建议复习的项目文件清单。
