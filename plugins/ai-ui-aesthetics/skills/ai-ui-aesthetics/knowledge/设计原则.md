# 设计原则（为什么美）

> 这是整个插件的审美内核。**先理解原则，再谈参数**。
> 所有 tokens/ 与 rules/ 里的具体值，都是为了实现下面这几条原则。

## 核心命题：美学 = 统一性 × 对比

界面丑，常常不是某个颜色错了，而是**全页面只有一种声音**——同样的字重、尺寸、颜色、间距，没有重点。高级感来自两件事同时成立：

1. **统一性（Unity）**：系统、组件、间距、圆角、色彩来自同一套规则 → 一致、可信、不混乱。
2. **对比（Contrast）**：通过大小、颜色、留白、明暗制造差异 → 有焦点、有节奏、不死板。

两条缺一不可。只有统一会单调；只有对比会混乱。**美 = 在统一里制造克制的对比。**

## 六大原则

### 1. 对齐（Alignment）
- 每个元素都与一个明确的视觉网格对齐，不随手放置。
- 尽量少用绝对定位，用流式布局 + 栅格。
- 同一层级的元素左/顶对齐，间距一致。
- **效果**：立刻显得专业。未对齐是最明显的「业余感」来源。

### 2. 对比（Contrast）
- 用大小、字重、颜色、明暗区分「重要」与「次要」。
- 一个页面应有一个清晰的**主焦点**（Hero、主按钮、核心数字）。
- 次要信息弱化（降低字重/颜色饱和度），突出主信息。
- **注意**：对比建立在可读性之上，文字与背景对比度至少达到 WCAG AA（正文 ≥ 4.5:1）。详见 knowledge/色彩.md。

### 3. 留白（Whitespace）
- 留白不是「空白」，而是设计元素，用来分组、隔离、引导视线。
- 元素越重要，周围越要留空间。
- 宁可留白偏多，不要拥挤。（参考：写码时默认多留白）
- **效果**：让界面「能呼吸」，显得高级与专注。

### 4. 层次与分组（Hierarchy & Grouping）
- 信息分层：用字号/字重/颜色/间距区分「标题 > 副标题 > 正文 > 标注」。
- 相关元素聚成组（视觉分组：留白、背景卡片、分隔线、边框）。
- 页面用「相近则聚、相异则分」的格式塔原则组织。

### 5. 一致性（Consistency）
- 同一个语义（主按钮/次要按钮/链接）全站视觉一致。
- 圆角、阴影、间距、字体同属一套 token，禁止随手指定新值。
- **效果**：用户无需重新学习，可信度高。

### 6. 平衡与视觉重量（Balance）
- 页面各区块分布均衡，不一边倒。
- 大色块/大图片有重量，小元素用分组与间距与之平衡。
- 对称或不对称平衡均可，但要刻意，而非偶然。

## 反单调清单（针对「界面丑是因为单调」）

| 检查 | 说明 |
| --- | --- |
| 有焦点吗？ | 页面是否有一个明确的视觉落点（主按钮/大标题/核心图）？ |
| 有层级吗？ | 字号/字重/颜色是否拉开了主次，而非一片平均？ |
| 有节奏吗？ | 间距是否有「松-紧-松」的变化，还是所有间距一样？ |
| 有质感吗？ | 是否至少有一处动效/阴影/渐变/玻璃等「细节」点缀？（见 rules/质感与动效.md） |
| 统一吗？ | 所有同语义组件是否来自同一套 token，无随手新值？ |

> 这四项都被满足时，页面既有「专业的一致」，又有「吸引人的亮点」。

## 一句话总结（可写进代码注释 / 提示 AI）
写界面时问自己：**这套界面来自统一的规则，且拥有一点克制的对比吗？** 答案两个都「是」，就是好看的方向。
