# 色彩（知识：如何配出「好看又协调」的配色）

> 目的：让 AI **不是随机选色**，而是按一套方法构建协调、有明确情绪、对比达标的调色板。

## 1. 色彩三要素
- **色相 Hue**：红橙黄绿青蓝紫。决定「是什么颜色」。
- **饱和度 Saturation**：鲜艳度。低饱和=柔和高级，高饱和=活泼冲击。
- **明度 Lightness**：亮暗。决定对比度与层次。

> 提示输出的调色板时，建议用 OKLCH 或 HSL 思考，分「明度阶梯」，而不是凭直觉给一堆 hex。

## 2. 一个页面该有几种颜色（克制原则）
- **主色 Primary**：1 个，品牌/主操作。占视觉主导。
- **强调色 Accent**：0–1 个，点缀/焦点（如链接、高亮、主按钮）。
- **中性色 Neutrals**：灰阶 5–9 级，用于文字、边框、背景、分层。**占界面最大面积**。
- **语义色 Semantic**：成功 / 警告 / 错误 / 信息，用于状态，面积小。
- **警示**：高饱和色**面积小**使用，大面积高饱和=刺眼业余。掌控好「少而精」。

## 3. 如何从主色构建一套可用的调色板
1. 定一个**主色相**。
2. 用同色相的第 50–900「明度阶梯」（类似 Tailwind/Radix 的做法）生成主色的亮/暗版本，保证对比可用。
3. 中性色单独建灰阶（带极轻微色相偏移，避免纯灰的死板）。
4. 强调色选主色的**补色或邻近色**（如蓝主 + 橙强调），只用于小面积焦点。
5. 语义色用直觉清晰的色（成功=绿、错误=红），并配足对比度。

## 4. 对比度（可访问性硬指标）
- 正文/文本对背景：**≥ 4.5:1**（WCAG AA）。
- 大号文本（≥24px 或 ≥18.5px 粗体）：**≥ 3:1**。
- UI 组件/图形边界与相邻色：**≥ 3:1**。
- 前景色应多在对比度足的「深/浅」区间，避免「中等灰 + 中等灰」。

## 5. 常见配色错误（AI 最容易犯）
| 错误 | 修正 |
| --- | --- |
| 随手给纯饱和度高的色做背景 | 背景多用低饱和浅色/深色中性，高饱和只给文字/强调 |
| 文字对比度不足（浅灰字） | 正文用足够深的色，浅灰只给禁用/次级 |
| 色彩过多、五颜六色 | 收敛为 主色+强调+中性+语义 |
| 没有明度阶梯，亮暗全靠 opacity | 建离散色阶，别用透明度叠色 |
| 用纯黑 #000 做深色背景 | 用带色相的暗色（如 #0f1115），更柔和 |

## 6. 情绪联想（选主色的依据）
- **蓝**：专业、可信、科技（SaaS 最爱）。
- **绿**：健康、增长、成功、环保。
- **橙/黄**：活力、温暖、提示、活力。
- **红/粉**：激情、热情、错误、年轻。
- **紫**：创意、高级、奢华。
- **中性/黑**：极简、高端、克制。

> 结合页面类型选情绪：落地页常用蓝/深色（可信），年轻品牌用撞色，工具类用中性+单强调。

## 7. 落地建议
- 颜色统一走 tokens/design-tokens.md（--color-primary / --color-surface / --color-text-* 等），禁止字面量散落。
- 需要渐变时，选同色相邻（相邻色相对比），并控制渐变方向与频率，保持可读性。
