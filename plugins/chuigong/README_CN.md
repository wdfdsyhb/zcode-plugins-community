# 垂拱 Chuigong — ZCode 放手委派插件

[English](README.md) | [简体中文](README_CN.md)

**垂拱**（出典《易·系辞》「垂衣裳而天下治」，后世称「垂拱而治」）是一个 [ZCode](https://zcode.z.ai) 插件，它把主对话变成垂拱而治的君上：君上只做**拆解、派发、裁决、汇总**，调研、写作、编码、批量数据、审核全部由五员预置百官子智能体（出厂钉定 GLM-5.3-Flash，可在**设置 → 子智能体**更换）执行——主模型昂贵的额度只花在君上的判断上，不耗在百官的中间产物上。三步安装：克隆本仓库 → 把克隆目录作为本地插件市场添加进 ZCode → 安装插件（见[安装](#安装)）。

## 工作原理

主对话模型贵，且上下文窗口是最稀缺的资源。信息分流看组织状态，不看体量：交接文档、项目主文档、README/DESIGN、需求纪要、spec、账本、审查包等已是结论形态的决策文档，由君上直读原文——这是拆解与裁决的输入，不算「做调研」；未整理原料（检索结果、日志、数据堆）遣百官消化成结论回传；已成文但体量巨大且仅局部相关的，遣官定向摘录并附行号锚点，君上按锚点精读关键段。垂拱的答案是一套委派经济学：

1. **角色预置。** 每员百官的完整角色定义随插件附带，派发只需填一份槽位简报——几十 token。
2. **产出落盘。** 百官把完整产出写进简报指定的交付文件，只回传状态加至多五行关键发现；主上下文看不到大体积内容。
3. **百官互审。** 每份产出都交御史按君上给的判据审核；FAIL 由君上先裁决，再把问题清单原样发回原官修复——默认至多 2 轮（sdd 严肃流程 3 轮），轮尽由君上接手。
4. **努力缩放。** 小任务＝遣一员直派；中＝2–4 员并行；大＝≥5 员分批（每批 ≤5）且交付路径互不重叠。紧耦合的工作明确**不拆**。

百官回报遵循固定四态契约：`DONE` / `DONE_WITH_CONCERNS` / `NEEDS_CONTEXT` / `BLOCKED`。失败沿升级阶梯上行：换更准简报重试 → 改派他官或拆小 → 君上亲自接手并在汇总注明。

**红线。** 破坏性删除、git 不可逆操作、系统状态变更、对外发布与外发数据、凭据值，**一律不派给百官**。百官自身也持硬契约：任务一旦触线必须回 `BLOCKED(红线: <条目>)`，不得变通。第一道防线更简单——这类步骤根本不进简报，由君上亲自执行（不可逆、外发类先请示用户）。

## 组件

| 组件 | 位置 | 作用 |
|---|---|---|
| SessionStart 钩子 | `hooks/` | 每会话注入君上守则（`startup` / `clear` / `compact`）——「君上只拆解、派发、裁决、汇总」规则的唯一出处 |
| `delegating` 技能 | `skills/delegating/` | 默认流程：分类 → 拆解（努力缩放＋反向闸门＋文件所有权）→ 简报填槽 → 四态分诊 → 审核 → 升级阶梯 → 汇总 |
| `sdd` 技能 | `skills/sdd/` | 严肃任务（多文件代码改动 / 高风险 / 不可逆）的严肃流程：逐任务实现者、逐任务审查、落盘账本、≤3 轮修复、整分支终审 |
| `grill-me` 技能 | `skills/grill-me/` | 究诘（需求拷问）：决策树追问直到没有未决决策；产出需求纪要 |
| `/wb` 命令 | `commands/wb.md` | 一键进入委派流程 |
| `/grill-me` 命令 | `commands/grill-me.md` | 对某主题或当前任务启动究诘 |

**百官名册**（全部定义于 `agents/`，出厂钉定 GLM-5.3-Flash，更换见[适配自己的模型](#适配自己的模型)）。五员各掌职司——通政采风纳奏（信息入朝）、翰林代拟文书、将作营建实施、书吏案牍批处理、御史监察验收：

| 百官 | 职责 | 工具策略 |
|---|---|---|
| `wb-researcher`（通政） | 君上的信息秘书：网络检索、来源核实、多来源对比；未整理本地材料（无文档代码库、日志、目录、数据堆）的测绘提炼；巨大文档的定向摘录（附行号锚点） | 全量继承你的工具集——保住 MCP 检索服务；写文件由角色文本约束 |
| `wb-writer`（翰林） | 起草、文档、报告、幻灯片、表格（docx / pptx / xlsx / pdf） | 全量继承 |
| `wb-coder`（将作） | 代码改动、脚本、修复、重构；强制自测；仅简报要求时才提交 | `Bash` `Read` `Write` `Edit` `Grep` `Glob` |
| `wb-data`（书吏） | 批量、机械的文件/数据处理，带计数对账 | `Bash` `Read` `Write` `Edit` `Grep` `Glob` |
| `wb-reviewer`（御史） | 验收审查：PASS/FAIL 判决加有证据的 Critical / Important / Minor 分级清单 | 只读工具＋`Write` 仅用于写自己的审核报告；内置红线扫描 |

**直读规则。** 已成结论形态的决策文档（交接文档、项目主文档、README/DESIGN、需求纪要、spec、账本、审查包）由君上直读原文：它们是拆解与裁决的输入，不是「调研」；遣官通读后再复读属于双重读取。`wb-researcher` 的车道只承接未整理原料与巨大文档的定向摘录。

## 安装

> **模型提示：** 出厂模型为 GLM-5.3-Flash；如需更换，到**设置 → 子智能体**下拉修改即生效。

### A. 本地市场源安装（推荐）

```bash
git clone https://github.com/rouyiemei/chuigong.git
```

1. 用上方命令把仓库克隆到本地任意文件夹。
2. 进入**设置 → 插件**，点**创建 → 添加插件市场**，选择克隆出的文件夹。
3. 在「**个人**」分段找到垂拱卡片 → 点**安装**。
4. 验证：**新开会话**——君上应当主动提议派发而不是自己动手；输入 `/` 确认出现 `/wb` 与 `/grill-me`。

**更新方式：** 在克隆目录里 `git pull`，然后到「市场源」面板点**刷新该市场**。

推荐这条路径的两个理由：

1. **钩子功能完整。** ZCode 官方插件开发教程写明：插件从官方市场或本地目录安装时，钩子才会运行。本地目录安装因此保证 SessionStart 君上守则注入完整生效——这正是垂拱依赖的核心机制。
2. **作者生产实测。** 这是作者本人生产环境在用的安装方式。

### B. GitHub 市场直加（备选）

1. 在 ZCode 中打开任意工作区。
2. 进入**设置 → 插件**，点**创建 → 添加插件市场**。
3. 填入 `rouyiemei/chuigong`（或粘贴仓库 URL），ZCode 会校验并克隆该市场仓库。
4. 在「**个人**」分段找到垂拱卡片 → 点**安装**。
5. 验证：**新开会话**——君上应当主动提议派发而不是自己动手；输入 `/` 确认出现 `/wb` 与 `/grill-me`。

### C. CLI 安装（备选）

```bash
zcode plugins marketplace add rouyiemei/chuigong
zcode plugins install chuigong@chuigong   # <插件名>@<市场名>
```

走代理的环境先给 ZCode 进程设 `ZCODE_HTTP_PROXY`——这是 ZCode 唯一认的代理变量（见[常见问题](#常见问题)）。

> **钩子与安装来源——依赖君上守则的用户必读（适用于方式 B、C）。**
> ZCode 官方插件开发教程写明：插件从官方市场或本地目录安装时，钩子才会运行。方式 B、C 都经本仓库这样的**第三方 GitHub 市场**安装，SessionStart 守则注入可能不生效（两处官方文档口径不一致，实际行为尚未完全确定）。垂拱的核心机制依赖这条注入，因此安装后请新开会话，确认君上确实在放权派活。若守则未注入，改用方式 A（本地克隆）——这是有保证的完整功能路径。

## 用法

```text
/wb 调研 ZCode 第三方插件的安装机制，把带证据的报告写到
    ./docs/research/plugin-install.md
```

接下来会发生什么：

1. 君上给任务分类（非纯问答 → 委派流程），并按复杂度定规模（此处：中，2–4 个方向）。
2. 以槽位简报指名派发 `wb-researcher`。角色定义已预置，简报只有几十 token：

   ```text
   对象：wb-researcher
   目标：ZCode 第三方插件安装机制，附官方出处
   边界：只依据官方文档与客户端实测；不推测；只动报告文件
   交付物：<./docs/research/plugin-install.md 的绝对路径>
   深度：medium
   ```

3. 通政检索、把完整报告写入文件，只回报：`DONE` · 文件路径 · 关键发现（≤5 行）。
4. 君上把判据交 `wb-reviewer` 审查 → PASS/FAIL 判决附证据。FAIL 时问题清单原样发回通政（≤2 轮），绝不静默丢弃。
5. 君上读报告文件，合成单一交付物，并注明分工。

需求本身说不清时，先别执行——先究诘：

```text
/grill-me 做一个跨机器同步笔记的 CLI
```

`grill-me` 分轮追问：每轮至多 4 道选择题（推荐项放第一位，只问前置决策已落定的「前沿」问题），直到没有未决决策，然后产出需求纪要到 `.chuigong/grill-me/<日期>-<主题>.md`。纪要确认后交回委派流程。究诘绝不未经你同意自动开始，也绝不在究诘期间做任何实现。

**为什么省额度：** 派发只花几十 token；未整理原料经百官消化成结论落盘，而非直接灌进对话；主上下文自始至终只见到状态、发现、最终交付物——以及需要直读的决策文档。

## 适配自己的模型

五员百官的模型由各自 `agents/*.md` 文件顶层 frontmatter 的 `model:` 字段出厂钉定，默认是账号系的 `account:bigmodel-individual-coding-plan/GLM-5.3-Flash`——GLM 套餐环境开箱即显即用，无需任何手动适配。

换用你自己的模型：安装后到**设置 → 子智能体 → 垂拱组**，在下拉框里为五员百官各选一个模型即可。修改写入 `~/.zcode/v2/agents-state.json` 覆盖层，独立于插件文件——市场刷新、插件更新都不会重置，一次设置长期有效；每员百官实际运行的模型也就在同一面板上核对。

任何便宜、快的模型都能保住这套经济学——百官模型应显著便宜于你的主模型。重调时留意两处有意为之的校准：`wb-data` 有意不跑深思考（它是快而规则化的车道），`wb-reviewer` 跑最高思考档。

## 插件审核要点

ZCode 官方插件文档要求的五项，各设专门小节。

### 用途

垂拱是委派与编排插件。会话开始时注入君上守则，指示主对话只做拆解、派发、裁决、汇总；五员百官子智能体与三个流程技能承担实际的调研、写作、编码、数据处理与审核。

### 依赖

- ZCode，支持插件提供的子智能体、技能、斜杠命令与钩子。
- **Windows：** Git Bash——SessionStart 包装器依次查找 `C:\Program Files\Git\bin\bash.exe`、x86 安装路径、`PATH` 上的 `bash`。**macOS / Linux：** 任意 bash。
- ZCode 中已配置可跑子智能体的模型。出厂默认为账号系 `account:bigmodel-individual-coding-plan/GLM-5.3-Flash`；更换见[适配自己的模型](#适配自己的模型)。
- 可选：MCP 网络检索服务（如 tavily、exa），供 `wb-researcher` 联网检索。
- 除此之外无任何依赖：无运行时包、无安装器、无构建步骤。

### 权限

安装后插件注册：

- 5 个子智能体，各带工具策略——通政与翰林全量继承你的工具集（含 MCP 服务器）；将作与书吏限定 `Bash` `Read` `Write` `Edit` `Grep` `Glob`；御史持只读工具加 `Write`，且 `Write` 仅可用于写自己的审核报告。
- 3 个技能、2 个斜杠命令、1 个 SessionStart 钩子。

角色文本约束每员百官只写简报点名的交付文件。子智能体不能再派发子智能体，也没有面向用户的提问通道。

### 网络访问

插件自带的代码不发起任何网络请求。网络活动只发生在百官通过继承工具访问你环境中的服务时——例如你配置的检索 MCP 服务器或命令行抓取工具——且仅当派发的任务需要时。百官红线均禁止把本地数据上传/POST 到外部地址，禁止任何发布行为。

### 副作用

- SessionStart 钩子脚本读取 `hooks/mandate.md` 并输出 JSON 上下文；注入的文本成为会话上下文的一部分。钩子不做脚本之外的任何执行。
- 任务运行所在的项目里，插件可能创建 `.chuigong/` 目录（sdd 账本、grill-me 纪要），并按简报点名的路径写交付/报告文件。请把 `.chuigong/` 加进项目的 `.gitignore`。
- Windows 上找不到 bash 时钩子静默退出：插件照常加载，但守则注入不生效（见[已知限制](#已知限制)）。
- 不改注册表、服务、计划任务；不安装任何东西；无遥测。

## 已知限制

1. **钩子依赖安装来源。** 据官方插件开发教程，钩子只在官方市场或本地目录安装时运行；经第三方 GitHub 市场安装时守则注入可能不生效。见[安装](#安装)一节的提示框。
2. **Windows 上钩子需要 Git Bash。** 缺失时钩子静默空转——不报错，也不注入。
3. **子智能体无法向用户提问**（平台约束）。需求澄清因此由主对话承担（`grill-me`）；百官只能回 `NEEDS_CONTEXT`。
4. **子智能体跨任务无状态。** 后续百官需要的信息必须写进简报或落盘文件。
5. **约束是提示词与策略层的，不是沙箱。** 百官以你 ZCode 环境的权限运行；红线体系是受控纪律，不是安全边界。不要把「意外执行也不可接受」的任务交给君上。
6. **`~/.zcode/agents/` 下的独立用户级定义不会被派发加载。** 若你的机器上存在与垂拱同名的旧用户级副本，不要编辑它们——请编辑插件级条目（**设置 → 子智能体** 中垂拱分组下的那五个）。
7. **偏好 deepseek 等第三方通道者。** 无需改插件文件：直接在 UI 把五员百官的模型换掉即可，覆盖层不会被插件更新重置。

## 常见问题

**添加市场后找不到插件。**
检查市场源面板里该市场是否通过校验并列出插件数；仓库根目录是否有 `marketplace.json`；克隆是否成功（代理问题见下一条）。

**新会话没有君上守则。**
确认插件已启用；确认钩子在 设置 → 钩子 中以只读条目出现；核对安装来源——经第三方 GitHub 市场安装时钩子可能不运行（见[已知限制](#已知限制)）。改用方式 A（本地市场源）重装即可恢复完整功能。

**走代理时克隆失败。**
添加市场前先给 ZCode 进程设 `ZCODE_HTTP_PROXY=http://host:port`。ZCode 只认这一个变量，裸的 `http_proxy` 会被忽略。

**百官报模型错误。**
出厂模型是账号系 GLM-5.3-Flash，非 GLM 套餐环境解析不到。到**设置 → 子智能体 → 垂拱组**，为五员百官各选一个你环境中可用的模型即生效——覆盖层不会被插件更新重置。见[适配自己的模型](#适配自己的模型)。

**百官回了 `BLOCKED(红线: ...)`。**
这是安全契约按设计生效。君上应当裁决：换一条没有红线操作的路径，或亲自执行该步（需要处先请示你）——绝不指示百官绕线达成同一效果。

**发新版后不提示更新。**
版本检测读取的是 `marketplace.json` 条目，所以发版必须**两处**同步 bump——`.zcode-plugin/plugin.json` 与市场条目（见[版本](#版本)），然后刷新该市场源。
