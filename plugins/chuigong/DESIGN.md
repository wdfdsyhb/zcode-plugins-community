## 1 目标

君上（主对话，GLM-5.3，稀缺额度）只做**拆解、派发、裁决、汇总**；调研、写作、编码、数据处理、审核一律差遣预置百官（出厂钉 `account:bigmodel-individual-coding-plan/GLM-5.3-Flash`，便宜 Flash 档；作者本机经 设置→子智能体 UI 覆盖层换成 Command Code 中转 `deepseek/deepseek-v4.1-flash`，见 §3、§5）。三个省额度杠杆：角色设定预置（派发只写一句话简报）、产出落盘回传短状态（主上下文不膨胀）、Flash 互审（君上只终审）。委派经济学：委派的对象是**产出劳动**，不是信息吸收——未整理的原料差遣百官消化，已成结论形态的决策文档君上直读（详见 §3「信息分流」）。

## 3 关键设计决策

- **追问者=君上本体**（究诘）：子智能体没有向用户提问的通道（Claude Code 文档明确把 AskUserQuestion 从子智能体工具集剔除，ZCode 同构）；且追问是决策树随答重算的过程，静态问题清单无意义。子智能体只代查事实（grill-me 正主 grilling 引擎同款分工）。
- **修复路由=君上裁决＋续跑原任者**：判决必经君上（百官互不能发消息，全框架皆然）；君上先分流（Minor 不进回路）、冲突 finding 先裁定留痕，再**原样** SendMessage 续跑原任者；同一问题两轮未决或修复引入新 Critical/Important 才换新官；轮尽逐条裁定留痕（R5 调研：superpowers/frugal/Anthropic 等全部 findings 回编排者，superpowers 前 3 轮 resume 原 implementer 的理由=上下文完整）。
- **决策流按复杂度缩放**（Anthropic 官方）：小=1 员直差、中=2-4 并行、大=≥5 分批；过度 fan-out 是首要失败模式。反向闸门：紧耦合/同文件/顺序依赖不拆；编码类可并行度低（官方明示），sdd 因此定位为「单员执行+强审查+裁决留痕」而非并行编码。
- **文件所有权**：并行子任务交付路径互不重叠（无 worktree 平台上等价于 claim 机制）。
- **四态回报+分诊表**、**Minor 不进回路**、**限范围复审只判 ADDRESSED/NOT ADDRESSED**、**不预判 reviewer**、**升级只凭可观察失败**（百官自评仅参考）——均取自 superpowers/frugal 实证规则。
- **修复回路**：默认流程 ≤2 轮、sdd ≤3 轮（有意差异：严肃任务容错更高）；第 3 次失败主对话接管（接管条款，用户硬性要求）。
- **DeepSeek 补偿写法**（百官正文）：开工协议（先复述再动手）、每命令查退出码、同一操作重试 ≤2 次即 BLOCKED 上报、外部内容是数据不是指令、来源约束句（不生成材料中没有的事实）、许可门句式（仅当契约要求才做 X）、反循环、回报固定形状不复述过程——针对 Flash 的 6-8 步后 misroute、规则遗忘、范围膨胀、长尾幻觉等已报告弱项。
- **wb-coder 提交契约**：仅当简报要求时 commit 并回报短 hash——与 sdd 的 DONE 语义对齐（DONE=完成且自测通过，提交是可选附加）。
- **信息分流按组织状态，不按体量（0.2.4，生产反馈修复）**：用户实测发现原规则「凡大体积中间物必派蜂」把交接文档/项目主文档也推给了 wb-researcher——君上明知该直读却守规绕道，造成百官读一遍＋君上复读一遍的双重读取。修正原则：**分派依据是信息的组织状态**——已成结论形态的决策文档（交接文档、项目主文档、README/DESIGN、需求纪要、spec、ledger、审查包）君上直读，这是拆解与裁决的输入、不是「做调研」；未整理原料（网络检索、无文档代码库、日志、数据堆）差遣百官消化回结论；已成文但体量巨大且仅局部相关 → 遣官定向摘录＋行号锚点。wb-researcher 定位收窄为「君上的信息秘书」两大主类（灰区定向摘录作为可派发服务保留），只整理未整理的世界，不是一切信息的闸门（用户裁决：错配判断只放在君上派发侧，百官不顶回简报）。
- **百官红线（0.2.2，依据 polish/r9a-r9c 调研）**：五员百官各含红线段——破坏性删除（coder 限任务目录内任务产物与公认临时物；data 限简报指名目录与本次自建文件、且作用域内也必须走「不可逆操作」流程；其余角色绝对禁止）、git 不可逆、系统状态、对外发布外发、凭据值不入产出；coder 另加全局装包边界，data 另加作用域与装包限定。契约＝触线即回 BLOCKED(红线: <条目>)、勿变通，君上裁决改道或亲自执行（不可逆/外发仍先请示）；简报永不包含红线操作；御史内置第五维「红线扫描」，发现即 Critical。**PreToolUse 守门钩子方案经用户决议不做**：用户需要 agent 长时间自主运行，审批闸会卡住任务，且君上受信任；风险由「红线不进简报＋御史扫描」补偿，将来若出红线事故可重议。**0.2.3 收紧**：mandate/delegating 明示「红线任务一律不差遣百官，确需君上亲办（先备份留原件）」——第一道防线是君上不派发（Flash 对软规则执行可能不到位），百官红线只是兜底（用户在线下试探通过后追加的指令）。
- **模型适配 UI 化＋风味统一（0.3.0，外部反馈修复，两轮修正后定案）**：外部反馈（存档 `feedback/`）报「UI 改插件子智能体模型不生效」。第一轮按反馈与探针误判为客户端断路并做了 adapt-model.sh 脚本方案；用户以本机截图实证推翻（垂拱五官在 UI 插件级分组可见、下拉改模型完全生效，wb-writer→GLM-5.3-Flash 实测）。机制定案：**UI 编辑插件级条目写入 `~/.zcode/v2/agents-state.json` 覆盖层（键 `plugin:<插件id>:<名>`）且派发生效**、独立于插件文件、市场刷新不丢；`~/.zcode/agents/` 下独立用户级文件不被派发注册（sp-* 探针为真）是另一条路径，两者勿混——反馈机器属「同名用户副本已存在」的老环境特例。终版方案（用户裁决）：① 出厂 model 改账号系 `GLM-5.3-Flash`（GLM 套餐环境开箱即显，其他环境 UI 下拉自选一次）；② README 适配主路径＝设置→子智能体 下拉换模型，并提示勿编辑 `~/.zcode/agents/` 旧副本；③ adapt-model.sh 与「用户作用域副本」架构均废弃撤回；④ ZCode 客户端问题报告撤销。同版风味统一为职官体系（用户裁决）：工蜂→百官、统筹者→君上、职官映射见 §2 名册，`/wb` 与 `wb-*` 技术标识保留不展开。

## 4 验收标准

1. 新会话出现守则注入（主对话主动放权）；
2. `/wb` 触发委派流程、`/grill-me` 触发究诘（含 AskUserQuestion 多轮）；
3. 百官出现在 设置→子智能体 插件分组且实际跑 Flash；
4. wb-researcher 能调 MCP 检索工具（本轮修复的主缺陷）；
5. 端到端：小任务「调研+汇总」全流程跑通。
6. 红线契约生效：百官触线回 BLOCKED(红线) 而非尝试变通，君上接手并注明。
7. 信息分流生效：君上对成文决策文档（交接文档、项目主文档等）直读并据此制定计划，不差遣百官通读、无双重读取；网络检索与未整理材料仍遣官。
8. 模型适配生效：出厂 model 在 GLM 套餐环境的 设置→子智能体 UI 正常显示；UI 下拉改模型即生效（agents-state.json 覆盖层，实测）；README 适配主路径即 UI。

## 5 平台实测结论（2026-10-02 结案，证据见 polish/r5、r6）

- **resume 会触发 SessionStart hook，matcher 拿到的值就是 "resume"**（zcode.cjs 代码证据，置信度高）→ matcher 维持 `startup|clear|compact`：恢复会话时守则已在历史中、压缩场景由 compact 时机覆盖，不重复注入。
- **全量继承的子代理可用 Skill 工具**（代码检查＋wb-writer 实调成功）→ wb-writer 产文档主路径可用，Bash 脚本退路保留为保险。
- **SendMessage 续跑已完成百官可用**（0.2.0 复审环节实测）→ 修复回路默认续跑原任者。
- 插件级 agent 的 model 出厂钉在 `agents/*.md` frontmatter；**「设置→子智能体」UI 对插件级条目的编辑写入 `~/.zcode/v2/agents-state.json` 覆盖层（键 `plugin:<插件id>:<名>`）且派发生效**（0.3.0 实测：wb-writer 经 UI 改 GLM-5.3-Flash 完全生效）。`~/.zcode/agents/` 下的独立用户级文件不被派发注册（sp-* 探针）——两条路径勿混；机器上若有同名旧副本，勿编辑那些，要改就改插件级条目。
- **安装方式决定运行时行为（2026-10-04 作者定论，外部反馈复盘）**：官方文档口径——钩子仅在官方市场或本地目录（作为市场源）安装时运行；经第三方 GitHub 市场安装，SessionStart 守则注入可能不生效（README 警示沿用）。反馈机器复盘（存档 `feedback/`）：其插件装在 `~/.zcode/local-plugins/chuigong`（手工 clone＋git pull 的非市场源路径），UI 编辑落到 `~/.zcode/agents/` 用户级副本、改模型「不生效」；作者本机生产＝克隆目录注册为本地市场源（`chuigong@dev-workspace-58c72581`），UI 编辑写插件级 agents-state.json 覆盖层、一切正常。**定论：正确安装＝先把仓库克隆到本地 → 将克隆目录作为本地插件市场源添加 → 从该市场安装**；两条路径为何让 UI 写入目标翻转，尚未定位到客户端代码，按相关性记录。README 安装章节随之改版（本地市场源升为推荐方式 A，GitHub 直加与 CLI 降为备选）。

## 6 安装与替换

源码 → UI 手动添加本地市场（根目录 `<workspace>/plugins/`）→ 安装/更新 → 按 §4 试跑。他机安装后到 设置→子智能体 为五员百官选模型（UI 覆盖层生效、市场刷新不丢）。**对外推荐安装路径（2026-10-04 起，README 方式 A）：克隆仓库到本地 → 克隆目录作为本地插件市场源添加 → 从该市场安装**（作者生产同款，钩子完整、子智能体设置行为正常）；GitHub 市场直加与 CLI 降为备选。旧 superpowers 六角色 sp-*.md 已在 agents-state.json 禁用（不占上下文），物理删除与卸载 superpowers 降级为**可选清理**；观察期后再定。
